South African landlord SaaS

Property management, made simple.

A standalone Angular 18 SPA that talks directly to Supabase from the browser — no API server. Tracks properties, tenants, rent, and payments in ZAR with timezone-safe (UTC+2) status math and an offline-capable PWA shell. Hosted as a static build on Vercel.

Key data flows

The eight most important runtime sequences inside Propza.

Email/password login

happy path
  1. LoginComponent.submit() calls AuthService.signInWithPassword
  2. Supabase Auth REST request; onAuthStateChange fires
  3. Signals session + user updated
  4. Router.navigateByUrl('/dashboard')
  5. authGuard + betaAccessGuard re-evaluate → allow

Google OAuth

redirect
  1. Click "Continue with Google" → signInWithOAuth({ provider:'google', redirectTo:'/dashboard?beta=granted' })
  2. Browser ↔ Google consent
  3. Return to /dashboard?beta=granted with hash; Supabase parses (detectSessionInUrl: true)
  4. App reads ?beta=granted hint, but localStorage flag still drives betaAccessGuard — minor inconsistency.

Property list load

combineLatest
  1. combineLatest([properties$, payments$, loading$])
  2. PropertyService.refreshAll() → loads properties (with nested tenants join) + payments
  3. Per-row status via RentDueService.getStatusForTenant(...)
  4. Client-side filter, search, sort → PropertyCard grid

Save payment + reconcile

retry on 23505
  1. Period = RentDueService.getCurrentPeriod() (YYYY-MM)
  2. INSERT payments; on duplicate-period (legacy unique constraint), advance month + retry × up to 12
  3. recalculateTenantStatusFromPayments() walks forward up to 12 months to find first unpaid period
  4. UPDATE tenants.rent_due_date + rent_status if changed
  5. PropertyService.loadProperties() refreshes; UI re-renders

Tenant delete cascade

multi-table mutation
  1. DELETE from tenants
  2. UPDATE properties SET status='vacant', tenant=null WHERE id=…
  3. SupabaseService.triggerRefreshAll() fan-outs to property + tenant services
  4. BehaviorSubjects emit; all subscribed views re-render

Theme sync

signal-driven effect
  1. Effect watches AuthService.user() signal
  2. On login: SELECT profiles.theme; if diff → apply + persist localStorage['propza_theme']
  3. User toggle: setTheme(t) → DOM class + UPDATE profiles.theme
  4. Logout clears the synced user id

Beta access gate

security: friction-only
  1. Guard reads environment.requiresBetaAccess; if false → allow
  2. Else checks localStorage['propza_beta_access']==='granted'
  3. BetaAccessComponent: 6 digits → btoa(code) === environment.betaAccessCodeHash → set flag
  4. Note: base64 is not a hash; trivially bypassed by anyone in DevTools.

Data export

latent bug
  1. Parallel SELECT * for properties · payments · tenancies
  2. Bug: queries payments.eq('owner_id', uid) but payments has NO owner_id column → returns empty
  3. JSON.stringify + Blob → propza-export.json download

Database schema

Five tables (3 migrated, 2 inferred). RLS owner-scoped via auth.uid().

properties

RLS enabled
  • id uuid PK
  • owner_id uuid → auth.users
  • name text
  • address text
  • rent_amount numeric/integer
  • currency text // always 'ZAR'
  • status text // vacant | occupied
  • lease_url text?
  • tenant text? // denorm, double-bookkeeping
  • notes text?
  • created_at timestamptz
  • updated_at timestamptz
⚠ Migration 001 declared different columns (status='available'/'maintenance', rent_frequency, bedrooms, etc.). Runtime schema diverged.

tenants

RLS via properties
  • id uuid PK
  • property_id uuid → properties (CASCADE)
  • name text
  • email text?
  • phone text?
  • rent_amount integer
  • rent_status text // paid|overdue|upcoming|vacant
  • rent_due_date date
  • lease_start_date date?
  • lease_end_date date?
  • deposit_amount integer // not in mig 003
  • notes text?
  • created_at / updated_at

payments

RLS via properties
  • id uuid PK
  • property_id uuid → properties (CASCADE)
  • period text // YYYY-MM
  • amount numeric
  • payment_date date
  • payment_method text?
  • notes text?
  • paid_at timestamptz
  • created_at timestamptz
History: unique(property_id, period) added in 002+005, DROPPED in 006 to allow partial payments.

tenancies (legacy)

undocumented
  • id uuid PK
  • property_id uuid → properties
  • start_date date
  • end_date date?
  • rent_due_day smallint // 1-31
No migration in repo. Still written by AddPropertyModalComponent & read by PropertyDetailComponent. Recommend deprecate → drop.

profiles

not in repo
  • id uuid PK = auth.users.id
  • full_name text
  • theme text // light|dark
  • notifications_enabled boolean
No CREATE TABLE migration. 004 RLS policies are wrapped in IF EXISTS. Fresh project will fail silently.

Storage · leases

bucket
PDF / document uploads for tenant leases.
  • path: {userId}/{timestamp}_{filename}
  • access: getPublicUrl() used by app
  • policies: not version-controlled

RLS · migration timeline

002
payments + unique(property,period)
003
tenants + permissive RLS + updated_at trigger
004
Owner-scoped RLS (auth.uid()=owner_id, EXISTS for child tables, profiles policies IF EXISTS)
005
payments.period (backfill via payment_date) + reaffirm unique
006
DROP unique constraint → allow partial payments
007
properties.notes column
⚠ Migrations 001 + 003 created permissive RLS policies. Migration 004 added the correct owner-scoped ones but never DROPPed the legacy ones. If both are active in production, RLS may be effectively bypassed for SELECT. Verify with SELECT * FROM pg_policies WHERE schemaname='public'.
